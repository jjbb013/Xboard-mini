二、安全漏洞与修复

1 Critical 4 High 9 Medium 4 Low

2.1 批量赋值（Mass Assignment）

严重程度文件问题描述
Critical app/Models/Setting.php $guarded = [] — 所有字段都可批量赋值，包括支付密钥、邮箱密码等敏感配置
High app/Models/User.php $guarded = ['id'] — is_admin, balance, transfer_enable, password 等敏感字段暴露
Medium app/Models/Plugin.php $guarded = ['id', 'created_at', 'updated_at'] — is_enabled, config 可批量赋值
Medium 多个模型 Order, Server, Coupon, Ticket 等均只保护 id，敏感字段开放

2.2 SQL 注入

严重程度文件行问题描述
High app/Http/Controllers/V2/Admin/UserController.php 144 orderBy($field, $direction) 的 $field 来自用户输入，Laravel 不转义列名
High app/Http/Controllers/V2/Admin/OrderController.php 139 同上，orderBy() SQL 注入
Medium app/Http/Controllers/V2/Admin/TicketController.php 33 orderBy($key, $value) 用户控制 $key
Medium app/Http/Controllers/V2/Admin/CouponController.php 36 同上
Low app/Services/StatisticalService.php 94-95 DB::raw("u + {$u}") 直接拼接变量

2.3 敏感信息泄露

严重程度文件行问题描述
High app/Http/Controllers/V2/Admin/ConfigController.php 166 Admin API 明文返回 email_password（SMTP 密码）
High app/Http/Controllers/V2/Admin/ConfigController.php 173 明文返回 telegram_bot_token
High app/Http/Controllers/V2/Admin/ConfigController.php 195 明文返回 recaptcha_v3_secret_key
High app/Http/Controllers/V2/Admin/ConfigController.php 198 明文返回 turnstile_secret_key
Medium app/Models/User.php 79 $hidden 只隐藏 password，token、uuid、password_algo、password_salt 在 API 中暴露
Medium app/Http/Controllers/V2/Admin/UserController.php 185 Admin 用户列表返回 token 字段

2.4 文件上传漏洞

严重程度文件行问题描述
Medium app/Services/ThemeService.php 121 ZipArchive::extractTo() 未校验路径遍历（../），恶意 ZIP 可写任意文件
Medium app/Services/Plugin/PluginManager.php 495 同上，插件 ZIP 解压无路径校验

2.5 认证授权与日志泄露

严重程度文件行问题描述
Medium app/Http/Middleware/Client.php 25 订阅 token 是静态单字段，无过期/轮换/频率限制，且 token 在多处 API 暴露
Medium app/Http/Middleware/Admin.php 24 is_admin 可被批量赋值（结合 Mass Assignment 可提权）
Low 多处控制器 — Log::error($e) 记录完整异常堆栈，暴露文件路径和代码结构
Low .env.example 2 默认 APP_ENV=local，直接复制到生产会开启调试模式

四、执行路线图

安全优先
🚨 第一阶段：安全修复（立即执行）
  • 修复 Mass Assignment（$guarded → $fillable 白名单）
  • 修复 orderBy SQL 注入（字段白名单校验）
  • 修复敏感信息泄露（Config API 脱敏、User $hidden 补充）
  • 修复 ZIP 路径遍历（主题/插件上传前校验条目）
🧹 第二阶段：文件清理（本周内）
  • 删除根目录 6 个开发笔记 markdown
  • 删除死代码（resources/js、sass、Test 命令、scribe 配置等）
  • 更新过时文档中的 Redis 引用
  • 清理 .docker/.data/redis/、config/theme/、public/web.config
✨ 第三阶段：功能增强（按需）
  • 优先：健康检查端点、SQLite 优化、Admin IP 白名单、数据库清理命令
  • 其次：Webhook 系统、审计日志、2FA、Prometheus Metrics
  • 长期：S3 备份、订阅暂停、GeoIP 控制

风险提醒

  • Mass Assignment 修复可能破坏现有 Admin API（如果前端依赖了某些字段的批量更新），需要逐个模型审查前端调用点
  • SQL 注入修复需要为每个受影响的控制器维护允许排序的字段白名单
  • Config API 脱敏需要确保前端不需要读取这些 secret 字段（通常前端只需要 key 名，不需要 value）
